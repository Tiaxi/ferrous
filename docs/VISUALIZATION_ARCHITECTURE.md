# Visualization architecture

## Playback and analysis

Playback owns audio output and publishes transport position and track identity. The position is the pipeline's own, with the `CLOCK_MONOTONIC` time the engine read it and whether it advances from there; the UI's `PlaybackClock` extrapolates it once, and the transport bar, spectrogram, waveforms, level meter, and MPRIS all read that clock. It does not forward unused PCM to the visualizations. Analysis opens independent decoders, preserving native sample rate and timestamped frame positions. Symphonia decodes the formats it supports; a file it cannot open, or opens but decodes no audio from, is read with GStreamer, as raw AC-3 and DTS always are. Symphonia cuts an MP3's encoder delay and padding, and an Ogg Vorbis file's pre-skip, as playback does, so frame 0 is the first sample that plays; Symphonia 0.5 cannot do this for AAC. Exact seeks decode codec preroll and trim to the requested frame. Spectrogram sessions align their FFT windows to an absolute sample grid, each centred on its column's time, so a sound shows in the column of the time it plays; timestamp gaps become bounded silence batches and overlaps are trimmed. Every channel of a view gets every decoded frame, also when the decoder's channel count differs from the file header's or changes mid-stream; a mono stream fills every channel. If the sample rate of a stream that GStreamer decodes changes mid-stream, as a DTS 96/24 stream's does where its decoder falls back to the 48 kHz core of a damaged frame, the decode converts the audio at the other rate to the rate the stream started at, on the stream's timeline; audio at that rate passes through untouched. The spectrogram, the overview and waveform detail all decode this way. Waveform detail preserves missing coverage separately from actual silence.

The analysis control thread owns track identity, display settings, generation changes, and gapless staging. It is the only thread that creates generations, and it neither reads files nor waits for the library database: a file helper thread reads file stamps, probes formats, and keeps decoded overview waveforms in memory and in the database. Stopped staging threads are not waited for until shutdown. A spectrogram worker owns its decoder, FFT scratch storage, peak-hold state, and partial output batch. For a stream of four or more channels that it decodes itself, it splits the channels between itself and up to two helper threads of its own, a batch of 64 FFT rows per channel at a time, and interleaves the columns in channel order, so the output is the one a single thread computes; streams that GStreamer decodes already decode on a thread of their own and stay on the worker. On Linux the spectrogram worker, its helpers, the centered staging thread, and the overview decode thread run ten nice levels below the rest of the app, so they give way to the UI, render, and playback threads when the CPU is busy; the streaming threads of GStreamer's analysis pipelines are not lowered. Seeking resets these objects without recursive decode loops or rebuilding FFT plans. Rolling continuation uses a continuous column timeline; centered transitions use the new track's timeline. The worker reports the format of each file it opens, and the control thread judges gapless compatibility from those reports rather than from probes. A continuation whose file does not fit is not decoded: the control thread starts the file afresh at the playback position. A session that cannot read its file clears the spectrogram and reports the error to the user; the worker then waits for the next session. A session that has to leave the columns it decodes for a playback position they cannot reach seeks where a restart would start: at the playhead when rolling, and before the left edge of the view when centered. It reports where, so the control thread judges later seeks by what is decoded. A seek, unlike a playback position, is passed on to the session as a seek. A rolling session always seeks for it. A centered session keeps its columns only if they cover the view of the target: the UI's ring still holds its left edge, and the playhead's column is decoded or next to be; otherwise it seeks before the left edge of the view at once, rather than decode every column up to it. A seek outside the window a centered session was started for restarts it instead. A centered session that starts left of its playhead, after a seek or a restart, decodes the playhead's columns first: from the playhead to 2 seconds past the right edge of the view, then the left of the view from where the session starts up to the playhead, then on from the right. Whenever playback brings the right edge of the view past what it decoded on the right, it goes back there before it finishes the left. Both sides are on the absolute column grid, and the session reports the end of its right side as what it has decoded. A right side that reaches the end of the file gives the file's extent, which every later chunk carries as its estimate, and the session publishes the end only once the left is sent: no column of a session comes after its end. A playhead past the end of the audio, where a duration estimated from a raw stream's bitrate can put it, gives a right side with no columns; the left then reaches the end of the file, and the session ends there, not at the playhead. A view that stops being centered does not get the rest of the left. The worker publishes a file's duration only if the file or its decoder tells it; raw AC-3 and DTS files tell it from their first frame header and the length of their frames, and until then a view has no end. Rolling sessions decode at twice realtime once the history a reset needs is filled, counting from the end of that refill.

## Ownership and backpressure

Spectral batches travel through a dedicated bounded channel to an FFI relay. Snapshot/control delivery remains independent. The relay serializes outside the UI queue lock and waits for queue space. The spectrogram worker is the only writer: the control thread hands it the chunks to emit before a session (staged columns, an immediate ring clear) with that session, so every chunk carries its session's generation and arrives in order. Generation changes discard obsolete output and interrupt blocked sends; shutdown wakes the relay explicitly. Rust and Qt must agree on command IDs, payloads, and FFI buffer ownership.

| Storage | Policy |
| --- | --- |
| GStreamer analysis appsink | Bounded queue; producers wait instead of dropping audio |
| Spectral output channel | Four batches |
| Serialized FFI spectral queue | 16 MiB |
| Centered next-track staging | At most an 8 MiB prefix |
| Speculative spectral lookahead | 64 MiB across channels, subject to the minimum visible window |
| Waveform PCM cache | 32 MiB LRU, 16,384-frame tiles, plus the tile holding the end of the file |
| Waveform summary cache, 64–512-frame levels | Separate 16 MiB LRU |
| Waveform summary cache, 1,024–16,384-frame levels | 16 MiB for the open file, filled in order and never evicted |

The lookahead policy is shared by Rust and Qt through `ferrous_ffi_spectrogram_ring_capacity`. It preserves one viewport of history in centered mode and two in rolling mode, in addition to lookahead. Visible-window requirements can exceed the speculative budget; this is not a hard process-memory ceiling. Decoder storage, render images, metadata, and allocations in flight are additional costs.

## Waveform queries

Detail requests run on Qt worker threads. A shared Rust service gives them one persistent decoder, held for one tile at a time, and caches PCM and min/max summaries; the level meter decodes between the tiles of a detail window. File identity includes path, length, and modification time, and one file is opened at a time. A cancelled request does not wait for the service; incomplete cancelled tiles are not cached. The summary pyramid starts at 64-frame blocks and supports coarser power-of-two queries without decoding again. Its levels from 1,024 frames up, about 6% of it, are kept for the whole file outside the LRU: whole-track and zoomed-out windows read every tile, and the full pyramid of a hi-res surround track (about 43 MB for five minutes of 96 kHz 5.1) does not fit the LRU, so they would decode the whole file each time. Once a window has read part of the file, a later window over that part at 1,024 frames a point or more decodes at most the two tiles its ends clip, and a whole-track window decodes nothing. The coarse budget holds about 26 minutes of 96 kHz 5.1, 13 of 192 kHz 5.1, or two hours of 44.1 kHz stereo; coarse windows over the rest of a longer file aggregate its fine levels if the LRU holds them, and otherwise decode it again. Clipped endpoints use PCM to avoid including samples outside the requested interval; a window that reaches the end of the file uses summaries for its last tile, and the PCM of that tile stays cached for windows that end just short of it.

The waveform editor has at most one detail request in flight. While playback moves the view on, that request stays as long as it covers part of the view, and its arrival asks for what it misses. A zoom, a resize, another track, or a seek to a view it does not cover cancels it.

Native channels and the arithmetic downmix have separate extrema: averaging channel extrema would destroy phase cancellation. The versioned WVF2 payload carries both. The compact whole-track overview remains a separate background job with a persistent cache, partial-coverage metadata, and peak-preserving reduction. It takes the peak of every decoded sample at the stream's own rate, whether Symphonia decodes the file or GStreamer does, in the analysis's pipeline. Its decode sends the first preview as soon as it has peaks enough to show, and later ones at most every 240 ms; a preview covers only the audio decoded so far. Only an overview whose decode reached the end of the file is saved, with the seconds it covers; one that an error stopped shows what it covers and is decoded again the next time the track plays. Loading a saved overview counts as a use, and the cache keeps the 4,096 used last.

## Channel positions

Channel positions are probed on the metadata worker using the same decoder selection as visualization analysis. The metadata protocol carries labels in native PCM channel order. Recognized speaker sets restore the status layout name and icon; unknown layouts retain the channel count. Waveform and spectrogram labels use the reported positions, falling back to numbers for unknown surround positions. Late layout metadata updates spectrogram text without replacing panes or clearing their history. The level meter remains unlabelled.

## Level meter

The horizontal meter occupies a fixed 20 logical pixels below the embedded visualization. Settings → Display → “Show level meter below the main visualization” controls its visibility and is persisted as `show_level_meter` (enabled by default). Both fullscreen viewer modes always hide the meter and give its space to the visualization. Hiding the meter clears its source and cancels pending queries. In the main view, its space comes from the playlist's initial preferred height; disabling it returns that space to the playlist. Stereo uses two 9-pixel bars with a 2-pixel gap; additional channels divide the same fixed height without labels.

The meter reads source levels before listening volume and channel mute/solo. It reuses the waveform service through the existing WVF2 interface, requesting at most 2,048 extrema points over two seconds on a Qt worker thread. One request may be in flight, with one current window and one staged replacement. Cancellation and generation checks discard results after seeks, track changes, pause, or hiding the view; failed reads retry after a delay. Only bins whose end has reached the transport playhead contribute to the display.

The scale runs from −60 to 0 dBFS with a subdued green/yellow/orange gradient. Each channel has immediate attack, 60 dB/s release (full scale to the floor in one second), and an independent one-physical-pixel-wide peak marker held for 1.5 seconds before falling at 12 dB/s. Elapsed-time ballistics apply each bin when it ended, so changing display refresh rate does not change hold or decay. Every bin since the previous frame counts once, also after the meter has been idle, and pausing or resuming first brings the levels up to that moment. During playback the bars show the levels as of the newest bin heard, not partway into the next, so a steady signal draws steady bars. The scene graph retains one shared gradient texture; bar ends and markers sit on device pixels. A frame is requested only when a bar or marker moves by a device pixel, or on a resize or scale change. Each presented frame advances the meter; with nothing to draw, a single-shot timer wakes it for its next change: the next pixel of a decay or the end of a peak hold, computed in closed form, or, during playback, the first upcoming bin that moves a bar, found by looking up to 0.5 seconds ahead in the current window. Steady levels, silence, held peaks, and a settled pause or stop draw no frames, and a settled pause or stop leaves no timer running. Pause lets the bars and held peaks decay; stop and transport discontinuities clear them.

## Qt rendering and visibility

Each spectrogram item owns its raw ring and rendered canvas under its state mutex. The ring takes memory in blocks of 64 columns, each when one of its columns is first written, so making room for a ring on a track, mode or FFT size change costs the GUI thread nothing however large the ring is; columns not written yet draw as missing. A rolling ring is written in the order the columns arrive. A centered session's ring keeps each column at the write sequence of its offset from the session's first column, which the worker's reset gives, so that the columns left of the playhead, which arrive after those right of it, land where they belong, and the ring drops the columns furthest left first; a column further left than the ring reaches from its newest is not written. Matching panes share immutable frequency-bin projection ranges and color lookup tables through weak references. Render passes retain their projection; image updates preserve previously retained `QImage` copies. This shares reusable rendering calculations without introducing a second global owner for mutable timeline state.

`BridgeClient` coalesces item/window visibility changes and enables spectral analysis when at least one registered item is visible in a visible, non-minimized window. Hiding all views stops decoding, cancels staging, and advances the generation. Transport and track changes still update analysis state. Showing a view starts a fresh generation at the latest position, including a viewport of rolling history. The non-Qt analysis API defaults to enabled.

A hidden pane skips animation ticks and canvas writes while retaining batches needed by another visible pane. Showing it invalidates the canvas. Hidden waveform surfaces clear their detail source, cancelling detail queries; the one-off overview cache job remains independent.

During playback the spectrogram and the waveform editor ask for a frame only when it would differ from the last one. A zoomed waveform that follows the playhead moves by whole device pixels: its view starts on a device pixel of the track's own grid, with the playhead on its middle pixel, and moves on a pixel when the playhead reaches its next one, so the frames between are the same and it changes only at those steps. A spectrogram that scrolls, rolling or centered, moves by whole device pixels: its canvas stays on the pixel it has reached until the scroll has gone a whole pixel further, so the column under a centered playhead is the one playing, as in a view that stays still. It changes only at those steps and when playback reaches the next column, which comes in at the right edge. A centered spectrogram that stays still, such as one showing the whole track, and a waveform showing the whole track or one of its ends, change only when the playhead reaches its next pixel or the view starts to follow it. The item works out, from the frame it last drew, when playback reaches that point on the clock's course, and wakes its frame with a single-shot timer; a frame that is already due is asked for at once. The spectrogram panes and the waveform editor of a window share one timer, with their frames due on a grid of whole milliseconds, so views whose pixels change together are drawn in one frame of the window. A spectrogram showing a zoom preview, or holding its position until data arrives, asks for every frame, as does a waveform while it draws the playback tiles of its view or a cache over several frames, or hands a zoom over. After a seek outside the decoded columns, a centered pane shows its previous image until the playhead's column arrives; the columns left of it then draw as missing until they arrive. A zoom shows its preview until its data covers the whole view. A clock sample that only corrects the course reschedules that frame; a seek, a track change, including a gapless successor or Repeat-One, and a pause show at once. Data, rasterizations, and property changes still ask for their own frames, except columns that a playing spectrogram receives ahead of the last ones it shows: they show only once playback reaches them, in frames it has already asked for. Texture nodes are only changed when their texture or placement does, so a frame that moves only the playhead leaves the canvas nodes alone.

With OpenGL, a pane's canvas is one OpenGL texture of the item's own, kept from frame to frame and split only where the canvas is wider than OpenGL's largest texture; Qt's scene graph draws it through `QNativeInterface::QSGOpenGLTexture`. While the scene graph synchronizes, with its context current, a frame uploads into it with `glTexSubImage2D` the canvas columns drawn since the last frame, in the order they were drawn: a rasterization's canvas first, whole, then the columns drawn over it since. Two spans of the texture draw the ring across its wrap and a third the newest column, all with one texture, so the renderer can batch them, and scrolling moves only those spans. A new scene graph or window makes new textures from the whole canvas; the old ones are deleted with their own window's context. Qt's public API cannot update part of a texture with other renderers, so they get the canvas in tiles of 64 columns, each made again when one of its columns changes; so does a canvas taller than OpenGL's largest texture, whose tiles Qt scales to fit.

The playback clock's own properties, which QML binds, change only when a view would show it: its text once a second, and its position by the step the transport bar asks for, a device pixel of the seek bar. The clock works out when playback reaches the next of either and wakes then with a single-shot timer; a seek, a track change, a pause, a resume or a change of the step shows the exact position at once. What starts from the position, such as a relative seek or a step of the seek bar's keys or wheel, reads the exact position from the clock on demand. A hidden or minimized window turns off the clock's timer. Its properties then follow the engine's samples, and catch up when the window is shown again. MPRIS reads the clock directly, and Last.fm's scrobble timing follows the backend's playback state, so neither depends on those updates.

## Validation and profiling

Run the checks in [DEVELOPMENT.md](DEVELOPMENT.md). Regression fixtures are synthetic or embedded and require no personal media or network access. Tests cover rolling and centered seeks, codec preroll, packet boundaries, timestamp gaps, track transitions, EOF, cancellation, stale generations, memory budgets, and Rust/Qt waveform payloads.

The optional [spectrogram benchmark](DEVELOPMENT.md#profiling) measures CPU canvas rebuilding with resident data. Its image checksums permit output comparisons. It does not measure decoder throughput, transport latency, GPU uploads, or end-to-end frame pacing; those require an instrumented application run on the target hardware.
